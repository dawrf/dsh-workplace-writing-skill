# 职场专业写作（Workplace Writing）

面向领导/客户的职场文档写作。默认风格：**专业严谨**。以下规则都是默认值；用户每次提出额外要求（字数、语气、禁用词等）时，以当次要求为准。

## 一、七条总原则（每篇都要遵守）

1. **结论先行**：开篇第一句就给结论，再展开理由和细节。领导没时间看铺垫。
2. **用数据说话**：能上数字就上数字（完成率、金额、时长、数量）。禁止「显著提升」「高度重视」「积极推进」这类无信息量的词——要么给数，要么删掉。
3. **一段一事，动词开头**：条目以「完成/推进/输出/解决/上线」等动词开头；一段只讲一件事；超过 3 行就该拆条。
4. **不编造**：用户没给的数字、人名、日期绝不虚构，用占位符 `[待补充：具体数字]` 标出，并在文末列出「需要用户补充的信息」清单。
5. **短句**：一句话不要装两层以上的意思，最好不超过 30 字。
6. **格式统一**：数字用半角；单位统一（万元/%，不混用）；日期统一 `YYYY-MM-DD`；层级最多三层：标题 → 小标题 → 列表。
7. **文末不留出处**：结尾不写「素材来源」「参考资料」「数据来源」等出处说明（除非用户明确要求保留）。

## 二、各类型的固定结构（硬性模板）

### 1. 周报 / 月报（默认 300–600 字）

```
标题：X 月第 X 周工作周报（YYYY-MM-DD ~ YYYY-MM-DD）
一、本周总览：一句话 + 1~3 个关键数字
二、本周完成：3~6 条，每条「做了什么 → 结果 → 数字」
三、问题与风险：如实写，每条附一句应对措施
四、下周计划：2~5 条，动词开头，可执行
五、需要的支持：没有就写「无」
```

### 2. 工作总结 / 述职（默认 800–1500 字）

```
标题：YYYY 年度（或 XX 阶段）工作总结
一、总体结论：一句话定性 + 核心成果数字
二、主要成果：分 2~4 个模块，每块「成果 → 数据 → 价值/影响」
三、方法与改进：做对了什么、沉淀了什么方法
四、不足与反思：2~3 条，客观归因（环境/方法/资源），不甩锅不卖惨
五、下一步规划：目标 → 关键措施 → 时间节点
```

### 3. 汇报材料 / 讲话稿 / PPT 大纲（默认 1500–2000 字；大会用正式材料可 3000 字以上，以用户要求为准）

```
一、背景与目标：为什么做这件事
二、当前进展：做到哪了（数据）
三、问题与方案：卡在哪、准备怎么办
四、需要的决策 / 资源：明确列出，让领导好拍板
五、下一步安排：时间表
```

### 4. 提案 / 方案

```
一、背景与问题：现状、痛点、不解决会怎样
二、目标：可量化的目标（数字）
三、方案设计：具体做法、资源投入、预期收益；如有 2~3 个备选方案给出对比并推荐
四、风险与对策：每条风险对应一条对策
五、落地计划：里程碑、负责人、时间
```

### 5. 商务邮件 / 公文

```
主题行：动词开头，一句话说清事（如「申请延长 X 项目交付时间至 X 月 X 日」）
称呼：尊敬的 X / X 总 / 各位同事
第一段：目的直接说（结论先行）
中间段：必要背景，分条
结尾段：明确的下一步或请求 + 截止时间
落款：姓名 + 部门 + 日期
```

## 三、语言规范

- 主动语态、主语明确：「我推进了 X」比「X 被推进」清楚。
- 少用形容词，多用名词和动词：「交付了 3 个版本」比「做了大量优化」有力。
- 不用网络用语、emoji、感叹号；少用「很/非常/特别」这类程度词。
- 涉及他人或团队成果时，把「我」和「团队」分清楚，不抢功不虚报。

## 四、写作流程

1. **问清四件事**（信息不全时一次问全）：文档类型、给谁看、篇幅要求、可用的素材（数据/事实）。
2. **整理素材**：把用户给的零散信息按对应模板分桶，缺什么立刻发现。
3. **搭骨架**：先写各级标题（对应上面的模板），标题本身要能读出信息。
4. **填充**：按总原则写内容，先保证信息准确，再打磨句式。
5. **自检**：对照下面的清单逐条过。
6. **交付**：输出 Markdown（带标题层级）；信息缺口以 `[待补充：...]` 标出，并在文末集中列出。

## 五、交付前自检清单

- [ ] 第一句是否就是结论？
- [ ] 每个「成果」后面有没有数字？
- [ ] 有没有「高度重视」「积极推进」这类空话？
- [ ] 每条是否动词开头、一段一事？
- [ ] 结构是否严格对应模板？
- [ ] 有没有编造的数据/人名/日期？缺口是否已标出？
- [ ] 字数是否在要求范围内？
- [ ] 格式（日期、单位、层级）是否统一？

## 六、示例：一条周报的前后对比

❌ 改写前（口语素材）：
「这周我们主要在搞那个新功能，整体还挺顺利的，比之前快了不少，用户反馈也不错。」

✅ 改写后（按本手册）：
「完成新功能「XX」开发并上线：开发周期较上版缩短 40%（15 天 → 9 天），上线一周用户好评率 92%（+8 个百分点）。」

## 七、特别说明

- 用户提供范文或历史文档时，先分析其用词、格式习惯，再在其基础上仿写；本手册规则与范文冲突时以范文为准。
- 用户对字数、语气、禁用词有额外要求时，当次以用户要求为准，不要照搬默认值。
